# واجهة حل التحدي — 2026-11-19

المسار: `/students/challenges/<challenge_id>/solve/` داخل لوحة الطالب.
تفتح بطاقات الاكتشاف هذا المسار بحسب الحالة: ابدأ الحل / تابع الحل / افتح التحدي.
يقبل حاليًا التحديات العامة فقط؛ قالب المسألة والمحرر مستقل عن ربط الوحدة ويمكن إعادة
استخدامه عند دمج تحديات الدورات لاحقًا. لا زر تحقق من الحل أو دمج بمنهج الدورة في هذه المهمة.

## الوصول والبيانات

تتطلب الصفحة جلسة و`LAB_EDITOR_API_ENABLED`؛ تستخدم `challenge_for_execution` ثم
`read_code` الحاليين. المنشور الحالي المتاح وحده، دون تعديل الإتاحة أو استيراد كود
نسخة سابقة. القالب يستقبل قاموسًا مسموحًا للمسألة وأمثلة `ChallengeExample`، وقاموس
المسودة العام؛ لا نموذج نسخة كامل ولا حل مرجعي ولا حالات اختبار أو مفاتيح Judge0.
الرد private/no-store. القراءة لا تنشئ مسودة أو تشغيلًا أو إنجازًا.

## المحرر والتجاوب

سطح المكتب: المسألة يمينًا والمحرر يسارًا، وفاصل قابل للسحب أو أسهم لوحة المفاتيح
وHome/End. النتائج تحت المحرر. الهاتف والشاشات المتوسطة: تبويبات المسألة والكود
والنتائج دون إزالة عقد DOM أو فقد النص والمدخلات وحالة التشغيل.
محرر textarea أصلي مع طبقة تلوين محلية آمنة وأرقام أسطر متزامنة بالتمرير، تراجع
وإعادة ونسخ وCtrl/Cmd+S، دون مكتبات جديدة أو أصول خارجية. تلوين أساسي وفق Python
أو JavaScript أو C++، وليس محلل لغة أو IntelliSense كاملًا. الواجهة RTL والكود
والمدخلات والنتائج LTR. عند غياب JavaScript تُعرض المسألة والكود مع تنبيه بأن أدوات
الحفظ والتشغيل تتطلبه، ولا يوجد نجاح وهمي أو تنفيذ محلي.

## الحفظ والتعارض

بعد 900ms من توقف الكتابة، باستخدام مسار POST الحالي وCSRF. طلب حفظ واحد في الوقت
نفسه؛ تعديل أثناء الحفظ يبقى محليًا ثم يُحفظ برقم المراجعة المؤكد. تأكيد الخادم وحده
يعرض تم الحفظ. الفشل يحتفظ بالنص ورقم المراجعة ويوفر «حفظ الآن»؛ انتهاء الجلسة يعرض
رابط الدخول. الكتابة العربية أثناء composition لا تشغّل حفظًا جزئيًا.
409 يوقف الحفظ التلقائي؛ لا إعادة محاولة برقم أحدث دون قرار المستخدم. يمكن نسخ
النص الحالي، ثم تحميل النسخة المحفوظة بعد تأكيد صريح. النص الفارغ المحفوظ يبقى فارغًا.
يطلب المتصفح تأكيد المغادرة عند وجود تغييرات غير مؤكدة. لا تخزين للحل المرجعي أو
بيانات التقييم في المتصفح، ولا حفظ محلي تلقائي لمسودة الكود خارج خدمة الحفظ.

## التشغيل والاسترجاع

إعادة استخدام POST `/lab/challenges/<id>/runs/` ثم GET الحالة من الاستجابة؛ CSRF
والحصص والالتحاق والملكية من خدمات التشغيل القائمة. التشغيل لا يكتب ChallengeSuccess.
أُضيف حقل `version_id` اختياري متوافق مع الطلبات السابقة، يُثبت في بصمة منع التكرار
ويُطابق المنشور تحت قفل القبول. رفض النسخة القديمة 409 `challenge_version_changed`،
حتى لا يفسر تبويب قديم الكود بلغة أو حدود نسخة جديدة. العقد القديم دون الحقل باقٍ.

يتعطل زر التشغيل طوال المهمة. يحفظ المتصفح **رابط حالة التشغيل فقط** في localStorage
بمفتاح المستخدم وUUID النسخة، ويسترجعه بعد إعادة التحميل؛ ملكية GET تُفحص في الخادم.
لا تحفظ tokens Judge0. لا polling خارج GET، ولا POST جديد آلي بعد قبول غامض. فقد رد
القبول يبقي الحمولة والمفتاح نفسه في ذاكرة التبويب، ويعرض استرجاع الحالة لإعادة الطلب
نفسه بقرار المستخدم. إذا أُغلق التبويب قبل استلام معرف التشغيل تضيع حمولة إعادة الطلب؛
لا ادعاء باستعادة هذه النافذة الضيقة تلقائيًا ولا إرسال بديل خفي. المعروف معرّفه محفوظ
في الخادم ويمكن متابعته بعد إغلاق الصفحة. الحالة uncertain تحتاج مراجعة المشغل.
المخرجات تُكتب بـtextContent ضمن سقف الخادم؛ أخطاء الخدمة منفصلة عن أخطاء الكود.

  تشغيل Python اصطناعي يجمع 2 و3 عبر Judge0 ويعيد 5؛ تكرار نفس الطلب يعيد السجل نفسه.
  التقرير المحلي المستثنى من Git: `deploy/judge0/.local/solve-preview-results.json`.
- بصمة قاعدة المشروع لم تتغير؛ لا ترحيلات أو اعتماديات أو تعديلات هوية.
- **الفحص البصري غير مكتمل**: browser access host غير متاح. لا صور أو ادعاء معاينة
  ناجحة للهاتف أو سطح المكتب أو لوحة المفاتيح أو الوضعين. اختبارات Node تختبر المنطق
  ولا تثبت سلوك DOM الفعلي أو جودة توزيع العناصر؛ تبقى هذه بنود قبول يدوي.
