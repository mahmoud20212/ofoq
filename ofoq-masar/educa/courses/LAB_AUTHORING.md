# أدوات إعداد التحديات ومراجعتها

طبقة التأليف فقط؛ لا صفحة تحديات عامة للطلاب ولا محرر حل أو تغيير للتقدم والالتحاق.
تستخدم `lab_services` للنسخ والمراجعة والنشر و`judge0_services` للفحص الحقيقي.

## المسارات

تبويب «تحديات البرمجة» بجانب المحتوى والاختبارات داخل إعداد نسخة الدورة:

- `/teachers/revisions/<revision_id>/challenges/`: القائمة
- `.../new/`: نموذج إضافة للدورة أو لوحدة من النسخة نفسها
- `.../<version_id>/`: جاهزية النسخة والفحص والإجراءات
- `.../<version_id>/edit/`: GET/POST لحفظ المسودة، مع CSRF
- `.../<version_id>/preview/`: معاينة شكل الطالب، دون بيانات التقييم الخاصة
- `.../<version_id>/review/`: الحل المرجعي وجميع حالات الاختبار للمخوّل
- `POST .../<version_id>/action/` مع `action=check`: طلب الفحص
- `GET .../<version_id>/state/`: حالة الفحص والعدد المنتهي والإجمالي وسبب آمن للتعذر

التحديات العامة في `/admin/courses/challengeversion/`. زر إضافة Admin يستخدم نفس
النموذج والخدمات. أدوات النسخة على `/admin/courses/challengeversion/tools/<version_id>/`
ثم `detail/`, `edit/`, `preview/`, `review/`, `action/`, `state/`.
لا حقول خام لتغيير الحالة أو مؤشر المنشور من Admin.

## التأليف والصلاحيات

التعديل للمعلّم المالك فقط في draft/rejected؛ نسخة الدورة قيد المراجعة تقفل تحدياتها.
تتحقق الخدمات من الملكية والقفل مرة أخرى تحت قفل الدورة/التحدي. لا نشر مباشر من النموذج.
Admin العام يحتاج staff و`manage_own_courses` للتأليف، أو staff و
`review_general_challenge` للمراجعة. تحديات الدورة تُراجع بصلاحية `review_course`.
تُمنح الصلاحيات عبر المجموعات القائمة دون منح إدارة المستخدمين أو إسناد تلقائي لحسابات.

الفحص المرجعي متاح لمالك التحدي المعلّم المحدد أو للمراجع المخوّل. تُعاد قراءة نشاط
الحساب وصلاحياته عند الطلب وفي العامل؛ الفحص لا يمنح اعتمادًا أو إدارة لمحرك التنفيذ.
تظل مزامنة اللغات وتفعيلها بصلاحية `manage_lab_runtime` فقط.

العام يستخدم خدمات `submit`, `withdraw`, `approve`, `reject`, `new_version` عبر POST.
الرفض يتطلب سببًا. يمنع المنشئ من اعتماد تحديه؛ استثناء superuser القائم فقط باقٍ.
تحديات الدورة تُرسل وتُسحب وتُعتمد ضمن نسخة الدورة ومعاملتها الذرية فقط؛ أضيف رابط
مراجعتها في CourseRevision Admin. لا تغيير لمحاولات الطلاب أو إنجازاتهم القديمة.

## النموذج والخصوصية

يدعم جميع بيانات المسألة والأكواد والأمثلة والحالات المرتبة والسقوف وسياسة المقارنة
وخيار الإتمام. كود البداية والحل LTR وبقية الواجهة RTL. الإصدارات الجديدة المعروضة
مفعّلة ومختبرة وبفهرس وبصمة تشغيل حاليين. اللغة المختارة مثبتة؛ تغييرها يحتاج نسخة جديدة.
السقوف من `LAB_RESOURCE_LIMITS`، ولا يستطيع المتصفح تجاوزها. تحفظ المسودة الناقصة،
والجاهزية من `validate_ready` الحالي. أخطاء الإدخال تعيد النموذج المرتبط بقيم الطالب.

الترتيب بحقل رقمي لكل مثال/حالة. «حالة ظاهرة للطالب» اختيار صريح؛ الباقي مخفي.
إضافة الصفوف تعمل بـJavaScript وبـPOST دون JavaScript يحتفظ بالمدخلات دون حفظ تلقائي.
الحقول أصلية ولها labels وتركيز واضح، وحالة الفحص تستخدم `aria-live`.

معاينة الطالب قائمة حقول مسموحة لا تتلقى `ChallengeVersion` أو private_snapshot.
تعرض الوصف والتنسيق والقيود وكود البداية والأمثلة والحالات الظاهرة فقط. العرض الخاص
منفصل ومحمي ويعرض الحل والحالات المخفية. لا تستخدمه مسارات الطالب أو استجابات النتائج.
كل القراءات الخاصة غير قابلة للتخزين المشترك.

## عامل الفحص المرجعي

أضيفت `queued` إلى `ReferenceVerification` القائمة. استدعاء
`start_reference_verification(..., defer_probe=True)` يتحقق محليًا ويحفظ لقطة وبصمة
وحالات الفحص ثم يعود **دون اتصال Judge0 داخل طلب الويب**. الطلب المكرر لنفس البصمة
والإعدادات يعيد queued/running/uncertain بدل تكراره.

العامل يستعمل `advance_reference_verification` الحالي وlease وtoken المحفوظين؛
يبدأ فحص الخدمة والتنفيذ خارج الصفحة. تغيير البصمة أثناء الانتظار يمنع الإرسال،
وتغييرها أثناء التنفيذ يمنع اعتماد الدليل. النتيجة القديمة تعرض `stale`. فشل الخدمة
لا يسجل نجاحًا. `uncertain` لا تُعاد تلقائيًا وتحتاج تسوية المشغّل.

```powershell
# من educa؛ المعاينة فقط
..\.venv\Scripts\python.exe -B manage.py lab_reference_worker --seconds 3 --settings=educa.judge0_preview_settings
# دفعة واحدة
..\.venv\Scripts\python.exe -B manage.py lab_reference_worker --once --seconds 3 --settings=educa.judge0_preview_settings
```

Ctrl+C يوقف العامل بعد خطوة الشبكة محدودة المهلة. إعادة التشغيل تستأنف بالمعرّفات
المحفوظة ولا تعيد POST لحالة مجهولة. `lab_judge0 report/resume` ما زالا متاحين.
لا يُستخدم عامل الطلاب. الترحيلان الإضافيان `0023_lab_reference_authoring_queue`
و`0024_lab_authoring_labels` طُبقا على المعاينة فقط.

## المعاينة والقبول الفعلي — 2026-11-19

الرابط: `http://127.0.0.1:55948/admin/login/`.
بيانات حسابي التأليف والمراجعة الاصطناعيين في الملف المحلي المستثنى من Git:
`deploy/judge0/.local/authoring-preview-login.txt`.
مساحة المعلم `/teachers/revisions/2/challenges/`، والعام من قائمة Admin أعلاه.
توجد مسودة ناقصة، وعام معتمد، وفحص فاشل، ونسخة تعديل أبطل تعديل حلها الفحص السابق.

| التجربة الفعلية في المعاينة | النتيجة |
|---|---|
| إنشاء عام ناقص من النموذج | مسودة محفوظة وغير جاهزة |
| عام صحيح، فحص Python 3.8.1 على AWS | اجتاز حالتين، إحداهما مخفية، ودليل مطابق للبصمة |
| تحدي وحدة، فحص حقيقي ثم مراجعة الدورة | اجتاز حالتين ونُشر ذريًا مع الدورة |
| المتوقع 6 بدل 5 في الحالة الثانية | failed ودليل غير ناجح، لا خطأ خدمة |
| فحص نسخة تعديل ثم تغيير حلها | stale والجاهزية مرفوضة |
| إرسال العام واعتماده بمراجع منفصل | approved ومنشور عبر الخدمات القائمة |
| HTTP فعلي للقائمة والنموذج وAdmin والمعاينتين وCSS وJS | 200؛ معاينة الطالب خالية من الحل والمدخل المخفي |

التقرير في `.local/authoring-acceptance-results.json`. القاعدة والوسائط معزولة؛
بصمة `educa/db.sqlite3` بقيت مطابقة. لم تتغير إعدادات Judge0 أو Keycloak أو الاعتماديات.
الجلسة وCSRF للمعاينة باسميْن منفصلين، فلا تستبدل جلسة الموقع على المضيف نفسه.
الخادم loopback فقط، مع DEBUG=False وrunserver --insecure لملفات المعاينة الثابتة؛
ليس إعداد نشر. العامل والنفق المملوكان للمعاينة مستمران. معرّفات العمليات في
`.local/authoring-preview-state.json`؛ أوقف فقط PID المتحقق من أمره، لا جميع Python/SSH.

**بقي الفحص البصري:** اتصال المتصفح المستقل غير متاح، ورفضت المراجعة الآلية نافذة
Chrome لأنها تعرض جلسة غير مرتبطة بالمهمة. لا صور أو ادعاء بنجاح فحص الهاتف أو
الوضعين اللونيين أو لوحة المفاتيح فعليًا؛ HTTP وفحص الشيفرة لا يثبتان جودة العرض.

## الاختبارات والملفات

النتيجة النهائية: **115 ناجحًا، صفر فشل وصفر تخطٍّ**، مع Django check سليم و
`makemigrations courses students --check --dry-run` دون تغييرات ناقصة.
بعد تحسين سبب الفشل المعروض، أعيدت اختبارات أدوات التأليف السبعة عشر: كلها ناجحة
أيضًا؛ هذه إعادة تحقق متداخلة وليست 17 اختبارًا إضافيًا إلى العدد السابق.

مجموعات معزولة: `tests_lab_authoring`, `tests_judge0`, `tests_lab_services`,
`tests_versions`, `tests_assessment_authoring`. SQLite والملفات والكاش والقنوات والبريد
معزولة؛ Judge0 في الاختبارات محاكاة، والقبول الفعلي منفصل في الجدول أعلاه.
صُحّحت تهيئة اختبار قديم لتاريخ محاولات الاختيار من متعدد بإكمال محتواه قبل البدء،
التزامًا ببوابة الفتح الموجودة، دون تعديل أي قاعدة وصول أو حساب تقدم.

الملفات الجديدة: `lab_authoring.py`, `lab_authoring_forms.py`, `lab_admin.py`,
`management/commands/lab_reference_worker.py`, `tests_lab_authoring.py`, هذه الوثيقة،
قوالب `templates/instructor/lab/` و`templates/admin/lab/`، وملفا CSS/JS باسم
`lab-authoring`، والترحيلان. عُدلت خدمات Judge0 وحالة ReferenceVerification ومسارات
المعلم وAdmin وتبويب المنهج وإعدادات المعاينة والاختبار القديم والوثيقتان المرجعيتان.
