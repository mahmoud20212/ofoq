# طبقة بيانات الاختبارات التعليمية

## شروط فتح الاختبارات للطالب

تُحسب عبر `assessment_requirements.py` من محتويات المنهج المنشور نفسها التي
يعرضها مشغّل الطالب، باستخدام Content.pk وسجلات ContentCompletion. النص
والصورة والفيديو والملف متساوية. اختبار الوحدة يتطلب إكمال محتويات وحدته؛
اختبار الدورة يتطلب إكمال جميع محتويات الدورة وتسليم محاولة في كل اختبار
وحدة معتمد متاح حاليًا. النجاح غير مطلوب؛ محاولة نشطة لا تكفي. يُعتد بأي
محاولة مسلّمة لنفس هوية الاختبار المستمرة، بما فيها نتائج النسخ السابقة.
الاختبار المسحوب أو المسودة لا يدخل ضمن المتطلبات. نطاق بلا محتويات لا
يضيف شرط محتوى وهميًا، واختبار بوحدة مفقودة أو من دورة أخرى لا يُتاح.

تعرض صفحة التقديم بيانات الاختبار وسبب القفل دون إنشاء محاولة. إعادة فحص
الشروط مطلوبة عند البدء وقراءة محاولة نشطة وحفظها وتأكيدها وتسليمها؛ مخالفة
الشروط تعيد JSON 409 مع `prerequisites_not_met` أو تعيد صفحة HTML إلى تقديم
الاختبار برسالة واضحة. إزالة إكمال أو إضافة محتوى منشور جديد قد تعيد القفل؛
لا تُحذف الإجابات أو المحاولات. النتيجة والسجل التاريخيان يظلان مقروءين،
وتكرار تسليم محاولة مسلّمة يبقى آمنًا. تستمر صلاحيات الملتحق للدورة المؤرشفة.
لا تعديلات على نسبة تقدم المحتوى أو البيانات الحالية أو قاعدة المشروع.

## واجهة حل الطالب

واجهة الطالب في `students/assessment_pages.py` وقوالب `students/assessments/`،
وتستخدم عمليات `assessment_services` نفسها دون تصحيح أو حساب نتائج في المتصفح.
تُحمّل قائمة الاختبارات المعتمدة وحالات محاولات الطالب دفعيًا عبر
`assessment_catalog()`؛ تظهر اختبارات الوحدة داخل وحدتها واختبارات الدورة
في قسم مستقل. لا خانات إكمال للاختبارات ولا مساهمة لها في تقدم المحتوى.

تحت `/students/courses/<course_id>/assessments/<assessment_id>/`:

- GET الصفحة الأساسية: تقديم الاختبار دون إنشاء محاولة
- POST `begin/`: بدء المحاولة أو العودة إلى المحاولة النشطة نفسها
- GET/POST `attempts/<attempt_id>/solve/`: الحل والحفظ والتأكيد والتسليم دون JavaScript
- GET `attempts/<attempt_id>/summary/`: النتيجة المحفوظة دون كشف الإجابات الصحيحة
- GET `history/`: سجل محاولات صاحب الحساب

مسارات JSON السابقة لم تتغير. مسح الإجابة يستخدم `option_key` فارغًا أو
`null` عبر العقد الموجود؛ النماذج ترسل اختيارًا فارغًا صريحًا. صفحة الحل تعرض
أسئلة وخيارات اللقطة بقائمة حقول آمنة، ودرجة النجاح وحد المحاولات للشرح فقط،
دون مفتاح التصحيح أو صحة الخيارات أو درجات الإجابات الفردية.

الحفظ يدوي؛ تبقى اختيارات المستخدم في الصفحة عند الفشل. استجابة حفظ طلب
أقدم لا تعيد كتابة الحقول التي عدّلها الطالب أثناء الطلب. التسليم يرسل
الاختيارات الحالية كلها بعد تأكيد عدد الأسئلة غير المجابة، ويمنع الحفظ
المتزامن. انقطاع رد التسليم يدخل حالة غير محسومة، مع زر قراءة حالة المحاولة
نفسها قبل إعادة المحاولة، دون بدء محاولة جديدة. انتهاء الجلسة يوفر دخولًا
في تبويب آخر واسترجاع الحالة، وتجدد قراءة JSON رمز CSRF عبر ترويسة
`X-CSRFToken` بعد المصادقة. لا تخزين محلي للإجابات أو مفاتيح التصحيح.

دون JavaScript تعمل نماذج POST وCSRF وخطوة تأكيد منفصلة تحمل الاختيارات
الحالية. جميع الصفحات غير قابلة للتخزين المؤقت وتتحقق من الالتحاق والملكية؛
يبقى وصول الملتحق للدورة المؤرشفة كما هو. النتائج التاريخية قابلة للقراءة
بعد سحب الاختبار، بينما الاستكمال والبدء يتطلبان إتاحته الحالية.

التحقق المستهدف يشمل `students.tests_assessment_ui` واختبارات العمليات
والتعلم والتقدم والاستئناف المتأثرة، واختبارات JavaScript للحفظ والاسترجاع
والمنهج والتقدم. المعاينة تستخدم قاعدة SQLite وملفات مؤقتة مستقلة، ولا
تُطبق الترحيلات على قاعدة المشروع. فحص HTTP ليس فحصًا بصريًا؛ تعذر تشغيل
أداة المتصفح، فتبقى مراجعة الهاتف والوضعين اللونيين ولوحة المفاتيح يدويًا.

## الموضع والنطاق

النماذج في `courses/assessment_models.py`، وتُستورد من `courses/models.py`
حتى تُسجّل ضمن تطبيق الدورات الحالي. لا تطبيق جديد ولا تغيير لنماذج
`ContentCompletion` و`CourseResume` أو أنواع المحتوى الأربعة أو حساب التقدم.
لم يكن هناك تنفيذ سابق للاختبارات التعليمية عند الفحص.

## نماذج التأليف والمراجعة

- `Assessment`: هوية ثابتة تتبع دورة، وحالة `draft` افتراضية، ورابط اختياري
  إلى نسخة منشورة. الإنشاء لا يتيح الاختبار.
- `AssessmentVersion`: العنوان والتعليمات ونسبة النجاح من 0 إلى 100 بدقتين
  عشريتين وحد المحاولات الموجب وتواريخ الإنشاء والتحديث. تتبع `CourseRevision`،
  ويمكن إسنادها إلى `RevisionModule` من نفس النسخة تحديدًا، أو تركها على مستوى
  الدورة. نسخة واحدة لكل اختبار داخل نسخة الدورة.
- `AssessmentQuestion`: نص وترتيب ودرجة موجبة بدقتين عشريتين.
- `AssessmentOption`: نص وترتيب ومفتاح صحة خاص بالخادم. الترتيب حسب `order, pk`.

تقبل المسودة عنوانًا أو تعليمات أو أسئلة أو خيارات غير مكتملة.
`validate_ready()` يتطلب عنوانًا وتعليمات وسؤالًا صالحًا واحدًا على الأقل،
ولكل سؤال نص ودرجة موجبة وخياران نصيان على الأقل وإجابة صحيحة واحدة بالضبط.
صلاحية الربط والنسب والأعداد تُفحص حتى في المسودة.

التعديلات العادية على نسخة اختبار أو أسئلتها أو خياراتها تُرفض عندما تكون
نسخة الدورة قيد المراجعة أو معتمدة أو متجاهلة. يُقرأ وضع النسخة من قاعدة
البيانات مجددًا لتجنب الاعتماد على كائن قديم محمّل في الذاكرة.

## أساس التكامل مع نشر الدورات

`validate_revision()` يفحص الاختبارات المرفقة قبل الإرسال والاعتماد.
`clone_snapshot()` ينسخ إعدادات وأسئلة وخيارات الاختبارات إلى نسخة العمل
الجديدة عند بدء التعديل أو استعادة نسخة، مع مطابقة وحداتها الجديدة، دون تغيير
مؤشر الاختبار المنشور. النسخ المعتمدة تبقى محفوظة.

اعتماد الدورة يستدعي `publish_assessment_versions()` في المعاملة نفسها، بعد
التحقق واعتماد نسخة الدورة. يُربط `published_version` بالنسخة الموافقة لها
وتصبح حالة الاختبار `published`. حذف اختبار من لقطة العمل يسحب إتاحته فقط
عند اعتماد تلك اللقطة، ولا يحذف المحاولات السابقة. أي فشل يعيد تغييرات قاعدة
البيانات الخاصة بالاعتماد والنشر معًا.
`is_available` يفحص هذه الشروط من البيانات الحالية، لكنه ليس تحققًا من
التحاق الطالب. يقبل حالة الدورة المؤرشفة تمهيدًا لوصول الملتحقين وفق قواعدهم
الحالية؛ لا يجعل الاختبار عامًا.

المسودة الجديدة لا تغيّر النسخة المنشورة؛ عند اعتماد تعديل أو استعادة تُنشر
الاختبارات الموافقة للقطة المعتمدة. لا تُنسخ التحاقات ولا تُمنح صلاحيات
بإضافة اختبار. توجد مسارات JSON للطالب وواجهة إعداد خاصة بالمعلّم؛ واجهة حل
الطالب وعرض نتائجه لم تُضف بعد.

## المحاولات واللقطة الخاصة

`AssessmentAttempt` يحفظ الطالب والاختبار ونسخة المصدر ورقم المحاولة وحالتها
ووقت البدء والتسليم. النتيجة والنجاح والدرجة الإجمالية والمحققة والنسبة كلها
`NULL` قبل التسليم؛ الصفر أو `False` ليسا بديلًا عن «غير محسوم».
بعد التسليم تلزم نتيجة كاملة ومتسقة، وتبقى ثابتة في الحفظ العادي.

`snapshot` حقل JSON خاص غير قابل للتحرير عبر ModelForm، لا يُجهّز للعرض العام.
صيغته ذات الإصدار `schema: 1`:

```json
{
  "schema": 1,
  "title": "عنوان الاختبار عند بدء المحاولة",
  "instructions": "التعليمات عند بدء المحاولة",
  "pass_percentage": "60.00",
  "max_attempts": 2,
  "questions": [{
    "key": "معرف السؤال الأصلي كنص",
    "text": "نص السؤال",
    "order": 0,
    "points": "3.00",
    "options": [
      {"key": "معرف الخيار الأول", "text": "الأول", "order": 0, "is_correct": true},
      {"key": "معرف الخيار الثاني", "text": "الثاني", "order": 1, "is_correct": false}
    ]
  }]
}
```

تُفحص صحة اللقطة عند حفظ محاولة جديدة، وتُرفض إعادة كتابة اللقطة أو هوية
المحاولة بعد إنشائها. خدمة البدء تبني هذه اللقطة من بيانات الخادم المعتمدة
داخل معاملة، دون قبول لقطة أو حد محاولات أو درجات من المتصفح.

`AssessmentAnswer` يحفظ مفتاح السؤال والخيار داخل **لقطة المحاولة**، وليس
ارتباطًا حيًا بخيار قد يتغير. يمكن ترك الخيار فارغًا لسؤال دون إجابة.
رابط السؤال الأصلي اختياري للتتبع فقط؛ يُفحص انتماؤه إن وُجد. لا تُمنح درجة
إجابة أثناء حالة الإجابة، ولا يُسمح بتعديل الإجابات المسلّمة بالحفظ العادي.

عند التسليم يُستخرج التصحيح من اللقطة فقط. النسبة المخزنة بدقتين عشريتين
تُقطع للأسفل (`ROUND_DOWN`) ولا تتجاوز الدرجات؛ النجاح يُقارن بالنقاط الدقيقة
وحد النجاح المحفوظ، وليس بالنسبة المعروضة المقربة. فحص الاتساق الموجود ليس
خدمة تصحيح بذاته؛ خدمة التسليم في `assessment_services.py` تحسب درجات كل
سؤال من اللقطة وتحفظها والنتيجة النهائية داخل معاملة واحدة.

## القيود وسياسة الحذف

- قيود قاعدة البيانات: نسبة النجاح 0–100، حد المحاولات ورقمها أكبر من صفر،
  درجة السؤال موجبة، رقم محاولة فريد للطالب والاختبار، وإجابة واحدة لكل
  مفتاح سؤال في المحاولة، وحالة نتيجة متسقة مع التسليم ونطاق درجات صحيح.
- هوية الاختبار تتبع الدورة بـ`CASCADE`، ونسخة الاختبار تتبع نسخة الدورة
  ووحدتها الاختيارية بـ`CASCADE`. حذف الوحدة لا يحوّل اختبارها إلى اختبار
  شامل للدورة. حذف نسخة منشورة يفرغ مؤشرها ويمنع إتاحتها.
- روابط المحاولة بالطالب والاختبار ونسخة المصدر `SET_NULL`؛ حذف المصدر أو
  الدورة لا يحذف سجل النتائج ولقطته. حذف السؤال الأصلي يفرغ رابط التتبع في
  الإجابة فقط، وحذف الخيار لا يمس مفتاح الخيار والنص المحفوظين داخل اللقطة.
- الإجابات تتبع المحاولة بـ`CASCADE`؛ الحذف المتعمد لسجل المحاولة نفسه حذف
  لسجله التفصيلي أيضًا، ولا توجد واجهة تتيحه حاليًا.
- علاقات الانتماء، وعدد الخيارات الصحيحة، وثبات JSON تُفحص في النماذج؛ لا
  يمكن التعبير عنها كلها بقيود SQL عابرة للجداول. `QuerySet.update` وعمليات
  bulk وSQL الخام تتجاوز حراسة `save` في Django وتبقى أدوات خادم موثوق فقط.
  يجب ألا تُستخدم لإسناد بيانات الطلب مباشرة أو للتحرير في طبقة العمليات.

## العمليات الخلفية

توجد في `courses/assessment_services.py`؛ مساراتها في
`students/assessment_urls.py` واستجاباتها في `students/assessment_views.py`.
كل طلب يتحقق من المستخدم النشط والالتحاق وانتماء الاختبار للدورة؛ تُقبل
الدورة المؤرشفة للطالب الملتحق وفق قاعدة الوصول الحالية. لا يستطيع المعلّم
الوصول لمحاولة طالب من هذه المسارات.

المسار الأساسي: `/students/courses/<course_id>/assessments/<assessment_id>/`.

| اللاحقة | الطريقة | المدخلات |
|---|---|---|
| `start/` | POST | `{}` |
| `attempts/` | GET | `?page=1`، عشرون سجلًا لكل صفحة |
| `attempts/<attempt_id>/` | GET | قراءة المحاولة وإجاباتها المحفوظة |
| `attempts/<attempt_id>/answers/` | POST | قائمة الإجابات مطلوبة |
| `attempts/<attempt_id>/submit/` | POST | `{}` لتسليم المحفوظ، أو قائمة إجابات |
| `attempts/<attempt_id>/result/` | GET | النتيجة بعد التسليم فقط |

كل POST يحتاج `Content-Type: application/json` ورمز CSRF صالحًا في ترويسة
`X-CSRFToken` وملف الجلسة. مثال الحفظ/التسليم:

```json
{"answers": [{"question_key": "12", "option_key": "30"}]}
```

الحفظ يحدّث الأسئلة المذكورة فقط ويحتفظ ببقية الإجابات. `option_key` فارغ
أو `null` يمسح اختيار السؤال. تُرفض مفاتيح JSON المكررة والأسئلة المكررة
والخيارات غير التابعة للسؤال والحقول غير المعروفة، بما فيها درجات أو معرف
طالب من المتصفح. عند وجود خطأ لا يُحفظ جزء من القائمة.

بدء جديد يرجع 201، وإعادة البدء ترجع 200 مع المحاولة النشطة نفسها. لا يُستهلك
رقم جديد بسبب إعادة الطلب. كل محاولة منشأة تُحسب ضمن الحد، سواء سلّمت أم لا؛
ويوجد قيد قاعدة بيانات إضافي لمحاولة نشطة واحدة لكل طالب واختبار. حد البدء
الجديد هو حد النسخة المنشورة الحالية مع احتساب جميع المحاولات السابقة دون
إعادة ضبط العداد عند النشر. حد البداية يبقى محفوظًا داخل لقطة كل محاولة.
خفض الحد لا يلغي محاولة نشطة؛ يمكن استكمالها، لكن لا يسمح ببدء محاولة أخرى
بعد نفاد الحد الجديد. `attempts_remaining` يعبّر عن الحد الحالي لا التاريخي.

استجابة البدء/القراءة/الحفظ تحتوي معرف المحاولة ورقمها وحالتها والعنوان
والتعليمات والأسئلة ونصوص الخيارات وترتيبها ودرجات الأسئلة والاختيارات
المحفوظة. لا تحتوي `snapshot` أو `is_correct` أو `pass_percentage` أو درجات
الإجابات المفردة أو روابط المصدر. `result` يساوي `null` قبل التسليم.
مثال استجابة التسليم/النتيجة:

```json
{
  "attempt_id": 7,
  "assessment_id": 2,
  "course_id": 1,
  "number": 1,
  "status": "submitted",
  "title": "اختبار الوحدة",
  "started_at": "2026-11-14T10:00:00+00:00",
  "attempts_used": 1,
  "attempts_remaining": 1,
  "result": {
    "earned_score": "3.00",
    "total_score": "4.00",
    "result_percentage": "75.00",
    "passed": true,
    "submitted_at": "2026-11-14T10:05:00+00:00"
  }
}
```

أسئلة دون إجابة تحصل على صفر. الدرجة موزونة بدرجة السؤال المحفوظة؛ النجاح
من المقارنة الدقيقة قبل قطع النسبة إلى منزلتين. تكرار التسليم يعيد النتيجة
المحفوظة ولا يصحح مجددًا؛ إرسال إجابات مختلفة بعد التسليم يرجع تعارضًا.
السجل والنتيجة السابقة يظلان متاحين لصاحبهما الملتحق إذا سُحب الاختبار من
النشر؛ بدء أو تعديل أو تسليم محاولة نشطة يتطلب إتاحة الاختبار الحالية.
النسخة القديمة للمحاولة تظل ثابتة عندما تُنشر نسخة جديدة صالحة من الاختبار.

الأخطاء: 400 للمدخلات غير الصالحة، 401 للزائر، 403 للحساب غير النشط أو CSRF،
404 لغياب الوصول أو عدم تطابق الدورة/الاختبار/صاحب المحاولة، 405 للطريقة
الخاطئة، و409 لنفاد المحاولات أو تسليم سابق يمنع التعديل أو نتيجة غير جاهزة
أو انشغال SQLite مؤقتًا. الاستجابات بلا تخزين مؤقت. رفض CSRF من Django قد
يرجع صفحة الخطأ القياسية بدل JSON، دون تعطيل حمايته أو تغيير إعداداته العامة.

## التزامن

كل تعديل يقفل صف `Course` على قواعد البيانات ذات أقفال الصفوف. على SQLite
يكون أول استعلام داخل المعاملة تحديثًا لا يغير قيمة حالة الدورة، لحجز قفل
الكتابة قبل قراءات عدد المحاولات أو الإجابات. اعتماد الدورة يستخدم الحجز نفسه.
تُعاد محاولة المعاملة القصيرة عند `locked/busy` حتى ست محاولات إن لم تكن
داخل معاملة خارجية، وبعدها يرجع 409 قابل لإعادة الطلب. القيد الجزئي للمحاولة
النشطة والفريد لرقم المحاولة يدعمان الحماية في قاعدة البيانات.

الحفظ والتسليم متسلسلان: إذا سبق الحفظ دخل في التصحيح، وإذا سبق التسليم
رُفض الحفظ اللاحق. لا يُستخدم قفل Python محلي للعملية بدل قاعدة البيانات.

## المتبقي لواجهات الطالب

بناء واجهة حل الاختبار واستكمال المحاولة وعرض السجل والنتائج وربطها بمسارات
الطالب الحالية. لا تضيف واجهة إعداد المعلّم نتائج طلاب أو مؤقتًا أو شهادات
أو أسئلة برمجية، ولا تغيّر حساب تقدم المحتوى أو الاستئناف.

الترحيل الإضافي `0016_assessment_data.py` ينشئ جداول وقيودًا جديدة فقط؛ لا
يعدل بيانات الدورات أو الالتحاقات، ولم يُطبّق على قاعدة المشروع الفعلية.
الترحيل `0017_one_active_assessment_attempt.py` يضيف قيد المحاولة النشطة؛
لم يُطبّق على قاعدة المشروع. إذا وجدت بيانات سابقة تخالفه يفشل التطبيق بدل
حذف المحاولات أو تعديل تاريخها تلقائيًا.

## تحقق طبقة البيانات السابقة

نجح 61 اختبارًا: 29 اختبارًا جديدًا في `courses.tests_assessment_models`،
واختبارات `courses.tests_versions` و`students.tests_learning_progress`،
وسبعة اختبارات نشر ومراجعة متأثرة من `courses.tests_instructor.InstructorTests`.
لا فشل أو أخطاء أو اختبارات متخطاة. فحص Django لم يسجل مشكلات، وفحص اتساق
ترحيلات تطبيق الدورات لم يجد فروقًا غير ممثلة بالترحيل الجديد.

التشغيل باستخدام `DiscoverRunner` داخل عملية إعداداتها معزولة: SQLite في
الذاكرة، ومجلدات وسائط ونسخ مؤقتة، وذاكرة تخزين محلية، وبريد وقنوات في الذاكرة.
حارس تشغيل يمنع فتح قاعدة فعلية أو كتابة ملفات خارج مجلد الاختبار أو الاتصال
بخدمات خارجية؛ يسمح فقط باتصالات الإيقاظ الداخلية اللازمة لـasyncio/Twisted
على Windows. لم تُسجل عمليات محظورة، وبصمة قاعدة المشروع قبل التشغيل وبعده
متطابقة. بقي تحذير Authlib السابق دون تعديل الاعتماديات.

## تحقق طبقة العمليات السابقة

نجح التشغيل المستهدف الحالي في **74 اختبارًا، دون فشل أو أخطاء أو تخطٍّ**:
29 اختبارًا جديدًا في `courses.tests_assessment_operations`، و29 لاختبارات
النماذج، واختبارات `courses.tests_versions` وسبعة اختبارات نشر ومراجعة متأثرة
من `courses.tests_instructor.InstructorTests`. استُخدم `DiscoverRunner` مع
الضوابط المعزولة المذكورة أعلاه، وبقيت بصمة قاعدة المشروع متطابقة، ولم تسجل
محاولات اتصال خارجي أو كتابة غير معزولة. فحص Django واتساق ترحيلات تطبيق
الدورات نجحا. لا حاجة لتشغيل اختبارات الواجهات أو JavaScript لعدم تعديلها.

اختبارات التزامن الثلاثة استخدمت خيطين واتصالَي Django منفصلين إلى قاعدة
SQLite الاختبارية المشتركة في الذاكرة: بدء متزامن، وحفظ مقابل تسليم، وتسليم
متزامن مكرر. نجحت دون نتائج جزئية أو تجاوز للحد. هذا لا يثبت سلوك ضغط طويل
أو عمليات تشغيل منفصلة أو PostgreSQL/MySQL؛ لم يُختبر أي منها. المعاينة
البصرية ليست ضمن المهمة ولم تُنفذ، ولم تُطبق الترحيلات على قاعدة المشروع.

## واجهة إعداد المعلّم

مدخل «الاختبارات» بجانب المحتوى التعليمي داخل الخطوة الثانية من إعداد نسخة
الدورة، مع بقاء تسلسل البيانات والمنهج والمراجعة الحالي. المسارات الخاصة:

- `/teachers/revisions/<revision_id>/assessments/`: قائمة اختبارات النسخة
- `.../new/`: إضافة اختبار ونطاقه وإعداداته
- `.../<version_id>/`: الأسئلة وجاهزية الاختبار
- `.../<version_id>/edit/`: تعديل الإعدادات
- `.../<version_id>/questions/new/` و`.../questions/<question_id>/edit/`
- `.../<version_id>/questions/<question_id>/<up|down|delete>/`: إجراءات الأسئلة
- `.../<version_id>/delete/`: حذف الاختبار من لقطة العمل فقط
- `.../preview/`: قائمة معاينات الاختبارات في نسخة الدورة
- `.../<version_id>/preview/`: معاينة شكل الطالب دون مفاتيح الإجابات
- `.../<version_id>/review/`: مفتاح الإجابات الخاص بالمراجع المخوّل

الإنشاء والتعديل متاحان للمعلّم المخوّل المالك فقط، بعد حد بيانات الدورة
الحالي، داخل مسودة أو نسخة تحتاج تعديلًا. تُقفل عمليات الكتابة على `Course`
بترتيب القفل نفسه الذي يستخدمه الاعتماد؛ ويُعاد فحص حالة النسخة قبل الحفظ.
النسخ قيد المراجعة والمعتمدة والمتجاهلة تُعرض للقراءة والمعاينة دون تحرير.
لا توجد صلاحيات أو مجموعات جديدة تمنح إدارة حسابات أو مستخدمين.

نماذج `assessment_forms.py` تستخدم تحقق النماذج الحالي، ونطاق حقل الوحدة
هو وحدات النسخة نفسها. جاهزية النشر من `validate_ready()` مع إظهار أرقام
الأسئلة الناقصة. لا تُكرر الواجهة تعريفًا مختلفًا للجاهزية. عنوان وتعليمات
وأسئلة وخيارات المسودة يمكن أن تكون ناقصة، مع استمرار التحقق من النسب
والأعداد والدرجات وانتماء المعرفات. صفوف الخيارات الإضافية الفارغة غير
المحددة كإجابة صحيحة لا تتحول إلى خيارات غير مقصودة عند الحفظ.

السؤال في صفحة مستقلة وخياراته فيها مباشرة؛ اختيار الإجابة الصحيحة مجموعة
radio واحدة، وترتيب الخيارات قابل للتحرير رقميًا أو بأزرار لوحة المفاتيح،
والأسئلة ترتّب بأزرار أعلى/أسفل. الإضافة الديناميكية للخيارات تملك بديل POST
يحفظ المدخلات دون حفظ السؤال حتى تأكيد الحفظ. لا نوافذ متداخلة.

الحذف يستخدم نافذة التأكيد الحالية للاختبارات والأسئلة، وحوارًا واحدًا لحذف
الخيار قبل حفظ السؤال. دون JavaScript توجد صفحات تأكيد للحذف، وخطوة تأكيد
إضافية للخيارات قبل الحفظ؛ فشل التحقق يبقي النصوص والقيم المدخلة. حذف اختبار
من نسخة العمل لا يحذف هوية `Assessment` أو النسخة المنشورة أو المحاولات.

معاينات GET محمية ولا تنشئ محاولة. معاينة الشكل تمرّر الأسئلة والخيارات
بقائمة حقول صريحة بلا `is_correct` ولا علامة جواب صحيح. عرض المفتاح المنفصل
يتطلب حسابًا نشطًا من الطاقم وصلاحية `courses.review_course`، وله مدخل من
صفحة نسخة الدورة في Django Admin. المعاينات لا تعرض نتائج الطلاب ولا توفر
تصحيحًا أو زر إرسال للطالب، وتستخدم `never_cache`.
