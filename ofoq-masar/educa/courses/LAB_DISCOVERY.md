# اكتشاف التحديات البرمجية العامة

المسار `GET /students/challenges/` داخل لوحة الطالب، مع رابط في تنقل مساحة الطالب
يظهر نشطًا عند فتح الصفحة. يتطلب جلسة مستخدم نشط؛ يوجّه الزائر إلى الدخول مع وجهة العودة.
الرد خاص وغير قابل للتخزين المشترك. لا كتابة في هذا المسار؛ POST مرفوض.

## ما يظهر

نسخة واحدة فقط لكل تحدٍّ: النسخة المعتمدة التي يشير إليها published_version حاليًا،
لنطاق عام غير مؤرشف. تفحص `available_general_versions` الإتاحة عبر
`challenge_for_execution` الموجودة، بما فيها اللغة والفحص المرجعي؛ لا اتصال Judge0
أثناء عرض القائمة. تحديات الدورات والمسودات والنسخ التاريخية وغير المتاحة لا تظهر،
ولا تدخل في خيارات اللغة والوسوم أو عدد النتائج.

تُمرر للقالب قواميس بملخصات مسموحة فقط: عنوان ووصف مختصر وصعوبة ولغة/إصدار ووسوم
وحالة الطالب. لا ChallengeVersion أو private_snapshot في قوالب الطالب، ولا حلول مرجعية
أو بيانات حالات اختبار ظاهرة/مخفية أو رموز. تعرض الصفحة ملخصات فقط دون رابط حل أو
زر تشغيل وهمي؛ ربط المحرر مؤجل للمهمة التاسعة.

الحالة لنفس الطالب وUUID **النسخة الحالية**:

- لم يبدأ: لا كود محفوظ ولا تشغيل ولا محاولة تحقق ولا نجاح.
- قيد الحل: حفظ كود، حتى الفارغ، أو تشغيل أو محاولة تحقق، دون نجاح لهذه النسخة.
- تم الحل: ChallengeSuccess حقيقي لنفس النسخة؛ فشل لاحق لا يلغيه.

التجميع بـ`with_learning_status` عبر EXISTS مفهرسة، مع نفس نماذج النشاط والسياسة
المستخدمة في `learning_status` الحالية. لا نداء حالة مستقل لكل بطاقة. نسخة جديدة
لا ترث كودًا أو نجاحًا قديمًا، وزيارة القائمة لا تنشئ نشاطًا.

## البحث والترقيم

GET بمعاملات اختيارية: `q` عنوان (حتى 200 حرف)، `language` رقم تعريف اللغة/الإصدار،
`difficulty=easy|medium|hard`، `tag` وسم كامل، و`state=not_started|in_progress|solved`.
جميع الشروط تُجمع معًا. تطابق الوسوم عضوية صريحة في القائمة، وليس بحث جزء من الوسم؛
يدعم SQLite دون contains غير المدعوم لقوائم JSON. القيم غير الصالحة تظهر خطأ حقل
ونتيجة فارغة، ولا تُفسر كفلتر آخر. معرّف طالب يرسله المتصفح لا يغيّر صاحب الحالة.

12 بطاقة لكل صفحة، مرتبة بالأحدث اعتمادًا ثم PK. روابط التالي/السابق تحفظ الفلاتر
الخمس، وخيار «مسح الفلاتر» يعود للمسار الأصلي. رقم الصفحة غير الصالح يطبّع عبر
Paginator.get_page. حالتان منفصلتان: لا تحديات متاحة أصلًا، أو بحث لا يطابق شيئًا.
النماذج GET أصلية وتعمل دون JavaScript؛ labels وتركيز واضح وRTL، واسم اللغة LTR.
التوزيع يتبع مساحة المحتوى بعمود/عمودين/ثلاثة، والحقول تتكدس للهاتف، مع دعم سمات اللوحة.

## إصلاح جاهزية المنشور مع مسودة أحدث

أظهر اختبار القائمة أن validate_ready كان يغيّر الحالة مؤقتًا إلى draft للتحقق،
ثم يفحص قيد نسخة العمل الواحدة كما لو أن النسخة المنشورة مسودة ثانية. استُثني
حقل status من full_clean الخاص بالجاهزية. التحقق العادي عند save وقيود قاعدة
البيانات وخدمات الحالات باقية؛ لا تجاوز للمراجعة أو دليل الفحص. توجد تغطية تؤكد
بقاء المنشور متاحًا مع مسودة أحدث، وعدم توريث النجاح بعد نشرها.

حُدّث أيضًا اختبار قديم من مرحلة البيانات كان يفترض عدم وجود Admin للتحديات؛ صار
يفحص أن أدوات Admin الحالية خاصة، لا تنشر تلقائيًا ولا تكشف serializer خاصًا.

## قبول المعاينة

الصفحة: `http://127.0.0.1:55948/students/challenges/`.
الدخول المحلي المعتاد للمعاينة من `/admin/login/?next=/students/challenges/`.
الحسابان الاصطناعيان السابقان في `deploy/judge0/.local/authoring-preview-login.txt`:
حساب التأليف يظهر «قيد الحل» للتحدي نفسه الذي يظهر لحساب المراجعة «لم يبدأ».
يُستخدمان هنا كحسابي طالبين، دون تعديل صلاحياتهما أو Keycloak.

أُعيد استخدام بيانات اصطناعية منشورة سابقة: العام المعتمد ذو عنوان «جمع عددين»،
مع نسخة عمل أحدث، وتحدي الدورة القائم. أُرشف تحدٍّ عام اصطناعي آخر بخدمة الأرشفة
القابلة للعكس؛ لم يُحذف شيء. حُفظ كود فارغ لأحد حسابي المعاينة عبر خدمة الحفظ الحالية
لإظهار «قيد الحل». لا إنجازات مصطنعة أو فحوص مرجعية وهمية أو تشغيل كود جديد.
التقرير في `.local/discovery-preview-results.json`، وبيانات المشروع الفعلية لم تتغير.

لا ترحيلات جديدة. الفحص البصري للهاتف وسطح المكتب والوضعين اللونيين ولوحة المفاتيح
لم يكتمل: browser access host غير متاح، ولا توجد نافذة معاينة محلية قابلة للتحكم.
فحص HTTP واختبارات HTML والتنسيق لا يمثلان معاينة بصرية ناجحة؛ لا صور مرفقة.

## الملفات والاختبارات

نتيجة التشغيل النهائية في 2026-11-19: نجح 112 اختبارًا، دون فشل أو تخطٍّ، وتشمل
المجموعات الأربع أدناه و`students.tests_dashboard`. قاعدة SQLite مؤقتة في الذاكرة،
وملفات وذاكرة تخزين وقنوات وبريد معزولة. فحص Django بلا مشكلات، وفحص
`makemigrations --check --dry-run` لم يجد تغييرات للنماذج، وبصمة قاعدة المشروع لم تتغير.
فحص HTTP الفعلي على المنفذ 55948 أعاد 200 للحسابين، وأثبت اختلاف الحالة وعرض
المنشور العام الحالي وحده واستبعاد الحل المرجعي؛ لا يُعد ذلك فحصًا بصريًا.

جديد: `courses/lab_discovery.py`, `students/challenges.py`, `students/tests_challenges.py`,
`students/templates/students/dashboard/challenges.html`, `courses/static/css/student-challenges.css`.
تعديلات: رابط التنقل ومسارات الطالب وعناوين الصفحات، تجميع الحالة في lab_editor_services،
تصحيح validate_ready واختباره القديم، وهذه الوثيقة وربطها بالوثيقتين المرجعيتين.

الاختبارات المعزولة: `students.tests_challenges`, `courses.tests_lab_editor`,
`courses.tests_lab_models`, `courses.tests_lab_services`. تثبت التصفية المركبة والترقيم
والحالات والنسخ والإتاحة والخصوصية، وتجميع حالات قائمة نسخ باستعلام واحد. لا اختبار
حمل أو ادعاء استعلام ثابت لكل بوابة الجاهزية؛ التحقق الحالي يُستدعى لكل منشور مرشح.
